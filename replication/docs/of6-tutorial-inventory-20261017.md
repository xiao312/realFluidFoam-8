# OpenFOAM 6 tutorial inventory — 2026-10-17

**`realFluidThermophysicalModels-6` supplies six property/counterflow cases; `realFluidFoam-6` supplies two nitrogen-jet LES cases.** Neither contains a premixed flame-speed sweep or nitrogen–hydrogen coaxial Case D4. This is a read-only Git source audit, not runtime qualification.

Pins: library `61f86014ef3f4277d04a348c83777d6a20d24cf3`; turbulent solver `3cc6aaca8e792c03c57011172092103b258f941c`. Cases were counted from every tracked `system/controlDict`.

| Tutorial under tutorials/ | Active setup |

| laminarCounterFlowFlame-2D/GRI30 | Same family; GRI30 selected through reactionsGRI and thermo.inputData_GRI; ode/seulex |

All property cases prescribe 100–2500 K across 1001 cells, have zero velocity and empty boundaries, and use `stopAt writeNow`, dt=1e-8 s. They are property-generation fixtures. All declare `application reactingFoam`; the repository includes a custom-linked reactingFoam target as well as realFluidReactingFoam, so binary/library identity must be verified. Pure-species chemistry is off. The mixture has chemistry on but an empty reaction set and inactive combustion configuration. SRK/ideal property dictionaries use the legacy `chemistrySolver` key where other cases use `solver`; actual OF6 startup remains untested.

Both counterflows use a 5-degree wedge, radius20mm, length20mm, 80 radial cells and axial sections40/60/40: **11,200 cells**. Both initialize at **2000K, pure CO2, zero velocity**. Fuel is CH4 at300K; oxidizer1000K with mass fractions O2=0.162 and CO2=0.838. Axial fuel/oxidizer velocities are +0.46806/−0.53194m/s for one-step and +0.467/−0.533m/s for GRI. Pressure101325Pa, total-pressure outlet; temperature outlet is inletOutlet with300K backflow.

One-step reaction is CH4+2O2=CO2+2H2O, A=5.2e16, beta=0, Ta=14906. GRI uses seulex, absTol1e-8, **relTol0.1**, initial chemical timestep1e-7s. Both use fixed flow dt1e-6s, PIMPLE1outer/2pressure correctors; endTime0.13s (one-step) or0.07s (GRI). Both startFrom latestTime.

The author README explicitly recommends using the one-step solution to initialize GRI30 and save compute. Commands are blockMesh then **realFluidReactingFoam**, despite application reactingFoam in the dictionaries. No automated transfer/Allrun script is supplied.

### Implication for the current campaign

This tutorial family is not newly discovered: our existing inputs already cite realFluidThermophysicalModels-8 revision301238a9450238f427021969127566866d679dd1. OF6 provides an additional historical reference. Distinguish that library repository from the nitrogen-only tutorials in the separately named realFluidFoam-8 solver repository.

Our generator uses1800K mixed reactants (newer campaigns can use localized ignition), GRI relative tolerance1e-6 instead of0.1, initial chemical timestep1e-8 instead of1e-7, molecular-weight-derived oxidizer fractions, computed inlet velocities and zero-gradient temperature outlet. Original GRI instead starts2000K pureCO2 unless the recommended one-step restart is supplied. Campaign mesh/time settings also differ. These are declared implementation choices, not proof of paper equivalence. A qualified one-step-to-GRI initialization could reduce development cost; species normalization, enthalpy consistency and final initialization sensitivity must be checked. This audit changes no running case.

## Turbulent solver repository

Two tutorials: c3.LEMOS.PR and c4.LEMOS.PR, both under tutorials/N2.jet.LES. Both use pureN2 at **3.97MPa**, ambient298K, PR/rfJanaf/chungTaka, chemistry off, Smagorinsky LES with vanDriest filter (cubeRootVol underneath). Inlets: c3=126.9K/4.9m/s; c4=137K/5.4m/s. Both enable decayingTurbulenceInflowGenerator, length scale0.11mm, Reynolds-stress diagonals0.24/0.29m²/s².

Both meshes have **4,158,000 cells**, from four sectors×(12+45+20)×30×450; axial length80mm, transverse extent±30mm, injector radius1.1mm. This count is dictionary arithmetic, not a fresh checkMesh result. Trigonometric #calc expressions need intended OF6 semantics verified when porting.

Both use fixed dt1e-5s, endTime0.3s, averaging enabled from0.15–0.35s (run covers only through0.3s), and64-way scotch decomposition. README/job invoke realFluidFoam while controlDict says reactingFoam. Both require external **LEMOS-6**, libInflowGenerator.so, and replacement of supplied site-specific Grid Engine/MPI scripts for SCNet Slurm.

Compared with OF8 solver tutorials, OF6 supplies turbulent-inflow variants for **both** c3 and c4, both4.158-million-cell meshes, active averaging and longer defaults. OF8 has c3/c4 fixed-inflow variants plus c3.LEMOS, different c3 mesh/time controls and cubeRootVol filtering. The 2025 paper's3.98MPa vs source3.97MPa and no-slip front wall vs sourcezeroGradient discrepancies persist in OF6. No OF6 case was compiled or executed in this audit.
